Local AI and Mission Control

A private, local-first AI assistant with a model router, a web control panel and voice.

Status
Active
Updated
November 2026
Repository
local-qwen-agent (private)
Goal
A private assistant that handles everyday questions, projects and home-lab tasks on local models, using the cloud only when allowed.
Where it stands
Mission Control, local routing and voice are in daily use. The services are being moved off the main desktop onto dedicated home-lab machines.

A self-hosted AI assistant that runs open-weight language models on a home GPU and only reaches out to cloud models when a request is eligible and the owner allows it. An agent layer keeps projects, chats and tasks organized, and a router decides which model may handle each request. Mission Control is the everyday web interface, designed to feel as simple as a mainstream chat app while keeping operator tools on a separate admin page.

Key features

  • Local-first routing: ordinary questions stay on a local model; cloud use needs explicit approval, spending caps and sensitivity checks
  • Mission Control web UI with Chat, Apps, Devices, Services and Import pages, installable on a phone as a web app
  • Voice conversation using local speech recognition and text-to-speech
  • Approval-gated actions: the assistant proposes changes and the owner confirms each one
  • Manages a small fleet of home-lab machines and containers, with read-only access by default
  • Self-hosted push notifications planned for a native Android app

AI Phone Control

Voice-triggered Android automations with a monitor that checks whether they actually worked.

Status
Active
Updated
November 2026
Repository
phone-control (private)
Goal
Reliable voice-controlled phone automations that confirm every action actually happened.
Where it stands
Workflows repaired and hardened; the outcome monitor, heartbeat and watchdog alerts are running.

A dedicated Android phone runs automation workflows that operate other apps on request, triggered by smart-speaker voice commands through a home automation hub. Because tapping through another app's UI can fail silently, a companion monitor watches each run, captures the screen state and classifies the outcome instead of trusting a simple success code. The project repaired and hardened an earlier set of workflows and added health checks so problems are noticed quickly.

Key features

  • Phone workflows wake the screen, read the target app's UI and act only when the expected state is present
  • Voice commands via a smart speaker and a home automation hub, plus a custom integration and skill
  • Node.js monitor that follows each run and sorts results into clear outcomes (failed, blocked, already on, confirmed, unconfirmed)
  • On-device text recognition fallback when animations prevent reading the UI tree
  • Heartbeat and watchdog alerts if the phone goes quiet or a scheduled run cannot be confirmed
  • Deliberately no blind retries after an uncertain result

Tech

  • JavaScript (Node.js)
  • Python
  • PowerShell
  • Android
  • Tasker

Camera Scan Station

Turning ordinary photos into 3D-printable STL models, no laser scanner needed.

Status
Active
Updated
November 2026
Repository
camera-scan-station (private)
Goal
Go from a physical object to a printable STL using only a compact camera, a turntable and lights.
Where it stands
A 12-view lighting and rotation capture test succeeded; checking photogrammetry reconstruction quality is next.

The goal is to go from a physical object to a printable STL file using only an off-the-shelf compact camera instead of an expensive laser scanner. Capture tools coordinate the camera (running custom firmware), a motorized turntable and two LED light bars to photograph the object from evenly spaced angles; photogrammetry then rebuilds those photos into a 3D mesh. Each session records its settings, and finished scans are audited and packaged with checksums for transfer to the reconstruction machine. A 12-view lighting and rotation test has succeeded; reconstruction quality is the next thing to validate.

Key features

  • Photo-to-STL pipeline: photograph an object, reconstruct a mesh with photogrammetry, export an STL
  • Automatic rings of photos at set angles, waiting for the turntable to settle before each shot
  • Saved presets for zoom, focus, ISO, aperture, shutter speed and lighting
  • Session metadata and camera logs recorded alongside the images
  • Audit tool checks image headers, dimensions, duplicates and inventory
  • Packaging and verification with SHA-256 checksums for safe transfer

  • PowerShell
  • Windows
  • CHDK

Office TV Cleanup and Launcher

Stripping the ads and tracking out of a Google TV, reversibly, plus a clean custom home screen.

Status
Maintained
Updated
November 2026
Repository
office-tv (private)
Goal
An ad-free, tracking-free Google TV with a clean home screen, where every change can be undone.
Where it stands
Working and maintained: ad and telemetry packages are disabled reversibly, and the custom launcher and screensaver are in use.

Smart TVs ship with home screens full of ads, sponsored rows and background tracking. This project removes them: scripts turn off the preinstalled ad, promotion and telemetry packages on an Android-based Google TV without uninstalling anything, so every change can be undone. It also replaces the ad-filled home screen with a lightweight custom launcher showing a clock, weather and an editable app grid, plus a screensaver of openly licensed photos with credits.

Key features

  • Removes home-screen ads, sponsored content and usage tracking by disabling those packages; nothing is uninstalled and everything is reversible
  • Tiered debloat script (ads, telemetry or all) and a matching restore script
  • Custom launcher: clock, date, weather, app grid with move and hide, and quick buttons
  • Screensaver slideshow of openly licensed photos with photographer and license credits
  • On-TV help screen explaining how to use the launcher
  • Documents which system packages were left alone on purpose and why
